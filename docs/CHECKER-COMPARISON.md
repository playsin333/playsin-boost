# Сопоставление BOOST 3.0.8 и TWEAK CHECK 2.0

Сверены исходники BOOST и чекера из коммита `424415c152c1138bf0dd565537edf043ae954803`. Это сравнение действий и оценок в коде, а не результат запуска на пользовательском ПК и не измерение производительности. В 3.0.8 твики и автоматические наборы не менялись.

## Какие проверки остаются отдельными

- Пункт 6 BOOST проверяет применённые паком значения относительно сохранённого состояния. Повторное применение настроек доступно вручную с подтверждениями.
- Пункт 14 запускает независимый TWEAK CHECK. Он сравнивает настройки Windows со своими эталонами и ищет следы оптимизаторов, включая BOOST. Эталон чекера не является бэкапом конкретного ПК.
- Одноразовый отчёт после входа остаётся отчётом BOOST. Запуск TWEAK CHECK не создаёт задачу для следующих входов.

## Пересечения, требующие разбора

| Настройка | Что делает BOOST | Как оценивает чекер | Что следует из сравнения |
|---|---|---|---|
| MMCSS / Tasks Games | `Invoke-SystemTweaks`: SystemResponsiveness=10, меняет приоритеты Tasks Games | «Плацебо» | Нужна отдельная проверка применимости к играм. Само успешное чтение реестра не подтверждает ускорение. |
| NetworkThrottlingIndex | `Invoke-NetTweaks`: 0xffffffff | «Плацебо» | Нужны основания для обещания пользы игровому трафику; это не универсальное снижение пинга. |
| TcpAckFrequency / TCPNoDelay | `Invoke-NetTweaks`: 1 на найденных интерфейсах | «Плацебо» с оговоркой про старые игры на TCP | Эффект следует проверять для конкретного TCP-приложения. Оценку нельзя переносить на UDP-трафик. |
| Win32PrioritySeparation | `Invoke-SystemTweaks`: 38 | «Спорно» | Эффект зависит от нагрузки, требуется сравнение на том же ПК. |
| Высокий приоритет через IFEO | В системном блоке — известные EXE; в профилях игр — по выбору | «Спорно» | Проверять плавность, звук и ввод под нагрузкой. IFEO относится к имени EXE, а не только к выбранному пути. |
| Задержки меню и автозагрузки | `Invoke-InterfaceTweaks`: убирает задержки интерфейса | «Плацебо», поясняет изменение поведения интерфейса | Пользовательское удобство и FPS — разные результаты; название оценки не отменяет изменение интерфейса. |
| Группировка svchost | Отдельный блок `Invoke-GroupingTweaks` | «Плацебо» | Блок не входит в три обычных автоматических набора. Сохранён для ручного выбора и расширенного максимума. |
| Сжатие памяти | При ≤8 ГБ включает, при ≥24 ГБ выключает, между оставляет как есть | Выключение на ≤8 ГБ — «Вред», при большем объёме — «Плацебо» | Для малой памяти поведение согласуется; основание отключать сжатие при ≥24 ГБ требует проверки. |

Системный и сетевой блоки с перечисленными наследуемыми настройками не включаются в три обычных автоматических набора. Они доступны вручную и в расширенном максимуме. Профили выбранных игр входят в игровой набор, но высокий приоритет выбирается отдельно.

Сначала нужно подтвердить механизмы и границы применимости спорных пунктов по первичным источникам, затем провести сравнения на Windows с одинаковой нагрузкой. По одной метке чекера настройки не удаляются и не откатываются. Отключение безопасности, изменение драйверов и удаление приложений также нельзя оценивать только по счётчику найденных изменений.

## Источник и проверка интеграции

В папке `checker` сохранены BAT версии 2.0+boost.1, лицензия MIT и `SOURCE.json` с исходным коммитом, исходной и локальной SHA256. Единственная локальная правка 3.0.10: пояснение SystemResponsiveness <10 исправлено на возврат к 20 по документации Microsoft MMCSS. Таблица выше описывает исходное сравнение 3.0.8; в 3.0.10 обычные наборы сохраняют сжатие памяти, а старые пороги доступны отдельно. Обновление чекера выполняется вместе с версией комплекта, а не скачиванием при каждом запуске.

Автоматически проверены синтаксис обоих BAT, совпадение исходника с закреплённой суммой, изоляция дочернего процесса, пути со спецсимволами, ошибка разбора и отсутствие файла. Диалог UAC, сбор реальных настроек Windows и открытие отчёта в Блокноте здесь не проверены.
