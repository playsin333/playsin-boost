# Проверка на Windows перед выпуском

Статус: проверки ниже ещё не выполнены в этой среде. Сначала виртуальная машина со снимком, затем реальные ПК по согласованным сценариям. Тестирование на Linux с имитацией не заменяет эти проверки.

| Сценарий | Проверяемое поведение |
|---|---|
| Windows PowerShell 5.1, Win10/11 x64 | Запуск гибридного BAT из папки с кириллицей, пробелами, апострофом и скобками; UAC и повторный запуск нужного пункта меню |
| Обычный пользователь / отдельный администратор | Настройка своей учётной записи, блокировка другой, корректные HKCU и рабочий стол |
| Диагностика и отмена | Не меняются параметры, папка бэкапа и задачи; недоступные сведения обозначены |
| Выбор блоков | Пустой выбор ничего не применяет. Выбранная сеть не запускает GPU, приложения или чистку; прежние функции доступны |
| Автонаборы | План совпадает с запуском; Appx и исключения Defender исходно не выбраны; запись клипов сохранена по умолчанию |
| Ошибка бэкапа | Нет права записи, заполненный диск, отказ File.Replace, повреждённый JSON: остановка с сохранением предыдущих файлов |
| Скрипт отката / ярлык | Отказ записи скрипта останавливает настройку. Отказ одного ярлыка не прячет рабочий скрипт |
| Параллельные запуски | Настройка, игра, откат и ручное исправление не меняют состояние одновременно. Второй клик игрового режима выключает первый |
| ACL и файловые системы | Текущий пользователь, Administrators и SYSTEM имеют доступ, другие пользователи не могут править повышенные скрипты. Старая папка, явные права дочерних файлов, NTFS/нестандартные диски, ссылки/reparse points |
| Повторная настройка / прерывание | Первый бэкап не перезаписывается; активный блок и частичный статус понятны. Отказ блока останавливает остальные |
| Реестр и конфликт отката | Восстановлены тип, значение и отсутствие исходного значения; последующие изменения сохраняются по умолчанию; явный выбор восстановления работает |
| Питание / ноутбук | Своя схема, сохранение DC-параметров, переключение AC/DC, недоступные параметры, Modern Standby, возврат предшествующей игровой схеме |
| GPU | NVIDIA без драйвера/без папки, импорт/сверка DRS, обновление драйвера; AMD с разными UMD/KMD; встроенная графика ноутбука |
| BCD / BitLocker | Включён, выключен и неизвестен статус; приостановка на одну перезагрузку, возврат защиты, отказ bcdedit |
| Приложения | Отмена подтверждения, удаление для всех пользователей/provisioning, классические замены, невозможность автоматического возврата данных отражена |
| Самопроверка после входа | Только отчёт: нет Set-Reg, удаления Appx, добавления исключений или изменения схемы. Отчёт выполняется один раз после явного разрешения, следующие входы его не повторяют; откат удаляет задачу |
| Ручное повторное применение | Только выбранные разделы; предупреждение о последующих изменениях; дополнительное подтверждение Appx; блокировка при игре/откате |
| Завершение / откат | Правильный статус при пропуске и ошибках. Восстановительные задачи и файлы доступны. Нереестровые ограничения понятны |
| Эффективность | Внешние сопоставимые игровые замеры, стабильность, температура и шум. Количество процессов не принимается за доказательство FPS |


Для 3.0.3 также проверить: Appx CurrentUser/AllUsers и provisioning на нескольких учётных записях; миграцию старой истории; сохранение уведомлений; выбор неизвестной автозагрузки и исключение аппаратных/защитных записей; профиль EXE с кириллицей/пробелами и несколькими GPU; адаптивную схему с прежними DC-параметрами; подключение/отключение зарядки во время игрового режима; сохранение настроек режима после повторной настройки; качество NVIDIA/AMD при отказе от изменения фильтрации; пункты 9 и 10 на установке 3.0.1/3.0.2.


Для 3.0.10 проверить на Windows: выбор 0/М/своего FPS, лимит и исходный возврат на NVIDIA и установленном RTSS (включая отдельные игровые профили), понятную ручную подсказку без RTSS; реальные возможности HAGS и смену после перезагрузки; сохранение прочих полей GPU-preference; явный MSI только на поддерживаемом оборудовании; два противоположных выбора сжатия памяти и возврат первого состояния. В игровом режиме — AC/DC на ПК и ноутбуке, политику Delivery Optimization 0/10 и её фактическое применение/удаление, уже имеющиеся политики и доменный ПК, закрытие окна, один возврат после входа и восстановление перед повторной настройкой. Пункт 10 должен сохранять разрешение одноразового отчёта. Нативные обращения к драйверам/RTSS и Планировщик в Linux не выполнялись.
