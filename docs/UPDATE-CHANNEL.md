# Обновление комплекта

Пункт 13 проверяет публичный канал, затем после одного подтверждения скачивает и проверяет ZIP. Новая версия устанавливается рядом; прежняя папка и резервные данные сохраняются. При недоступном канале можно явно выбрать локальный ZIP. Пункт 9 обновляет служебные скрипты, а не сам BAT; повторное применение настройки для этого не требуется.

## Источник

`PLAYSIN-BOOST-update-source.json`:
```json
{"ManifestUrl":"https://raw.githubusercontent.com/playsin333/playsin-boost/main/boost-release.json"}
```

Источник рядом с папками версий имеет приоритет. В 3.0.12 точный прежний официальный URL на pc-optimizer разрешается в новый публичный канал, без изменения исходного файла. Произвольные пользовательские источники сохраняются. Для старых BAT первый переход на 3.0.12 выполняется вручную.

## Сборка

```text
python tools/package.py releases/v3.0.12/PLAYSIN-BOOST-3.0.12.zip --sync-metadata --check-metadata --archive-url https://raw.githubusercontent.com/playsin333/playsin-boost/main/releases/v3.0.12/PLAYSIN-BOOST-3.0.12.zip --release-manifest boost-release.json
python tools/verify_release.py
```

Версионный ZIP и manifest публикуются одним коммитом. Старые архивы не переписываются. Любое изменение файла пользовательского комплекта требует новой версии и пересборки. Видеоматериалы, assets, документация разработки и тесты исключены из Download ZIP и пакета обновления.

Клиент проверяет HTTPS без встроенных паролей, продукт, версию, SHA256 архива и файлов, структуру и синтаксис BAT. Подпись издателя не реализована; хеши не удостоверяют автора недоверенного источника.

Лимиты: JSON 64 КБ, ZIP 32 МБ, распакованные файлы 64 МБ суммарно / 16 МБ на файл, пять HTTPS-переходов. Тесты обновления используют временные папки и имитацию сети и запуска. Они не подтверждают реальный UAC, драйверы или откат на каждом ПК.
